Chromosome 22 Structural Variant Benchmarking Report

1. Aim

This report summarises the chromosome 22 benchmarking workflow for HG002 structural variant calls from DRAGEN, Sniffles, and DELLY against the truth set in both hg19 / GRCh37 and hg38 / GRCh38. The report focuses on diagnosis, preprocessing, benchmark interpretation, and DUP-to-INS sensitivity analysis.

2. Key findings

  • Best original Truvari F1: hg19_sniffles (F1 = 0.752)
  • Largest DUP-to-INS F1 increase: hg19_DELLY (ΔF1 = 0.0000)
  • Smallest / most negative DUP-to-INS F1 change: hg19_DELLY (ΔF1 = 0.0000)
  • Total BND records counted separately: 192
Main interpretation: The core benchmark should be interpreted as an interval-SV benchmark. BND records, END<POS issues, and missing END / SVLEN issues were counted and visualised separately so the reader can see what was excluded and why.

3. Diagnosis

The original chr22 subsetting problem came from chromosome naming mismatch:

  • hg19 / GRCh37: chromosome label 22
  • hg38 / GRCh38: chromosome label chr22

4. Benchmark scope

The main interval-SV benchmark includes:

  • DEL
  • DUP
  • INS
  • INV

The following are handled separately and interpreted as exclusions / QC context rather than direct interval benchmark targets:

  • BND
  • UNKNOWN
  • NA
  • missing SVTYPE
  • malformed interval records

10. Interpretation

The figures above should be used to interpret both performance and representation sensitivity:

  • Precision / recall / F1 plots show overall caller performance in the original benchmark.
  • Original vs DUP-to-INS plots show whether differences are due to biology / caller performance or due to representation.
  • BND plot shows the number of records that were counted separately because they are not directly comparable as interval SVs.
  • END<POS and missing END / SVLEN plots show why some records needed QC handling before benchmarking.

In practical terms:

  • If DUP-to-INS barely changes the metrics, then the original results are stable to representation differences.
  • If DUP-to-INS clearly improves recall or F1 for a caller, then some apparent misses were likely due to DUP vs INS representation rather than completely wrong calls.
  • A high BND burden reminds the reader that not all structural variants fit cleanly into interval-style benchmarking.

11. Main conclusion

The chromosome 22 workflow was successfully debugged and benchmarked. The original empty chr22 subsets were caused by chromosome naming mismatch, and the later analyses showed:

  • which variants entered the interval benchmark,
  • which categories were handled separately,
  • how original caller performance compared across runs, and
  • whether DUP-to-INS conversion materially changed interpretation.

12. Limitations

  • This is a chromosome 22 subset, not a whole-genome benchmark.
  • The main benchmark is interval-SV focused.
  • BND and complex events require separate interpretation.
  • Representation differences (especially DUP vs INS) can affect apparent performance.
